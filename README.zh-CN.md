# R5 VLA 中文指南

[English](README.en.md) · [项目首页](README.md)

## 项目范围

本项目整理了 ARX R5 从遥操、数据采集到 LingBot-VLA 真机部署的完整工程流程。采集是两台机械臂一主一从；模型任务只有一台执行臂。相机为从臂腕部和外部固定 Gemini 305。Ubuntu 22.04、ROS 2 Humble、系统 Python 3.10 用于硬件侧，训练及推理使用独立服务器环境。

不要直接运行旧脚本。工程源代码在 `reference/host/*.in`，它们保留了已有实现，不是全新重写的通用机器人框架。`scripts/materialize.py` 仅替换路径及设备身份，输出到默认被 Git 忽略的 `runtime/`；不导入工程模块、不启动硬件，也不提交作业。

## 按顺序进行

1. 阅读[安全边界](docs/safety.md)和[依赖安装](docs/setup.md)，通过独立安装获取固定版本上游源码及原厂 SDK。
2. 使用 `config/site.local.json` 配置路径和 CAN 设备身份，生成本地运行副本。原始 GitHub 快照不会随本地配置改变。
3. 按[遥操指南](docs/teleoperation.md)核对两臂身份、CAN0/CAN1、普通夹爪 1:1 映射及初始化行为。启动 SDK 可能使能和回零，不是只读操作。
4. 按[录制指南](docs/recording.md)启动双相机，先录制 test-only 测试，再批量录制正式示范。开始/停止录制不改变遥操控制。
5. 按[数据格式](docs/data-format.md)核对时间戳、图像、状态、标签与回合边界。任务名相同并不足以合并数据。
6. 数据上传、校验及[训练](docs/training.md)在服务器完成。先 CPU 数据检查、官方基座校验，再按正常 Slurm 队列提交；`nice=0`，不修改其他用户作业。
7. 按[部署指南](docs/deployment.md)完成权重和归一化绑定、只读预测、现场准备，再由操作员手动启动模型执行。不能同时遥操和模型控制同一从臂。
8. 测试时可独立录制图像与状态；结束后导出双视图 MP4。保留原始 MCAP，导出视频不是原始采集数据，也不能充当硬件同步证明。

## 已有实验配置与结果边界

任务为 `Put the charger in the box`。四批正式记录中选取 71 条人工标注成功示范，共 24,576 帧；全部用于训练，没有独立验证集。独立从官方 `robbyant/lingbot-vla-v2-6b` 基座开始，两张 GPU，global batch 32，训练 4000 次更新，2000/4000 步分别保存。

部署输入为双 RGB、从臂六轴绝对位置与夹爪原生值、任务文本。模型输出未来 50 条七维绝对目标，每段按名义 30 Hz 发布，执行完再重新观察；推理等待会打断连续发布节拍。500 是目标条数上限，不是 500 个闭环推理回合。

已有一次日志记录发送 300 条模型目标后，操作员按回车报告完成。这证明出现了模型驱动的实际执行，不证明整体成功率、自动成功判断或全程无人工干预。模型权重、原始数据和视频均未随仓库发布。

## 快照与可移植性

- `reference/host/training_v1` 仍包含 71/12 条数据计数、历史 session 名称、2000/4000 步等实验绑定；换数据时需显式修改及重新校验。
- 部分任务执行和归位脚本使用固定 SDK SHA、二进制偏移或示范初始姿态。这些是特定版本的工程实现，不能通过改 SHA 强行适配另一版 SDK。
- 用户现场修改过若干速度/跟踪检查；本次导出保留现状，不把已注释的检查描述为仍启用，也没有因整理仓库而进一步放宽控制逻辑。
- 旧代码注释或日志标签可能过时。以本仓库当前文档、实际源码和重新生成的验收证据为准。
